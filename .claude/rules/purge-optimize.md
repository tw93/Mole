# Purge and optimize

- `purge` (`bin/purge.sh`, `lib/purge/scan.sh`) removes project build output directly through `mole_remove_artifact`. A folder qualifies only when its name is in `mole_purge_target_table` and the folder beside it holds the matching project file (`node_modules` next to `package.json`, `target` next to `Cargo.toml` or `pom.xml`, `.venv` with `pyvenv.cfg`, .NET `bin` with `Debug`/`Release`, pytest/mypy/ruff caches by their own `CACHEDIR.TAG`); `vendor` only beside `composer.json`. Never offered: a `.git` or `*-keypair.json` inside, any file git tracks, `node_modules` without a lockfile and the manager's install record or with files newer than that record, anything not the user's. A project a user process works in (cwd, exe or a path argument, Mole and its ancestor shells excluded) and folders changed within 7 days start unselected; `--yes` takes only the old ones; every check runs again right before removal, and a probe that times out keeps the folder. Roots: `$XDG_CONFIG_HOME/mole/purge_paths`, else default folder names plus home folders that hold a project within two levels (not media folders, `~/go` or dot folders); `/` and the home itself are never roots; the walk stays on the root's filesystem, depth 6, prunes dot folders that are not targets and never descends into a match. `__pycache__`, `DerivedData` and `Pods` are not targets (tiny or macOS only). `build`, `dist`, `coverage`, `vendor`, `bin`, `obj` and `_build` are offered only inside a git repository, and a `.git` at or above the project that git cannot read keeps the folder. "In use" means a process's cwd, exe, path argument or `VIRTUAL_ENV` is inside the project, or sits exactly in a folder above it, up to the scan root, that is a project itself (a monorepo's top), or is anywhere in a JS workspace (`pnpm-workspace.yaml`, `workspaces`, lerna, nx, turbo) that holds it; Mole's ancestors are skipped only while they are shells or Mole's router; a repository at the home itself never counts as "inside a git repository"; when `/proc` cannot be read every project is in use. The picker has no select-all key.
- A project counts as in use when any other process of this user has its working folder, program, path argument, `VIRTUAL_ENV`, an open file or a mapped file inside it. `mole_purge_other_pids` ends its list with `done` and prints `unknown` for a running process whose status cannot be read (`mole_purge_pid_mine` 2; the shared `mole_pid_mine` answers 1 there), and either gap fails the snapshot. `mole_purge_proc_holders` ends its output with an end mark only after both listings finished; xargs 123 finishes only when every collected error is a process that exited or denied reading, since a `find` that could not start is also 123; any other status or a timeout leaves the mark out, the snapshot fails and every project reads busy. Locked by the `mapped from a project`, `vanished`, `unfinished holder scan` `only an exited or refused process` and `owner cannot be read` cases in `tests/purge.bats`; the mapped case calls libc `mmap`, because Python's `mmap.mmap` keeps a duplicate descriptor and passes without the maps read.
- `optimize` uses no sudo. It changes only the user's font cache, launcher index, personal icon theme caches and the SQLite files of closed browsers and Thunderbird (Chromium family: History, Favicons, Web Data, Top Sites, Shortcuts, never Cookies or Login Data; Firefox, Zen and Thunderbird: every top-level `*.sqlite` except `cookies.sqlite`) (read through `mode=ro&immutable=1` so a dry run leaves no `-wal`/`-shm` behind, quick_check first, VACUUM only when 1MB or more comes back, never above 100MB, never through a symlinked profile or file, and the running-browser probe is asked again before each file; a browser that runs or a probe that cannot tell skips it); everything that would need root or a choice (failed units, broken launchers and autostart, `pacman -Qtdq`, a stale `db.lck`, only when no package manager runs under any user, root included, TRIM, two power managers) is reported with the command to run. A systemd question with no running systemd (`/run/systemd/system`) or no user bus is "unavailable", never "healthy". Its report-only items also cover Hyprland start commands, user unit programs and dangling `wants` links that point at missing programs, and root-owned files in `$HOME` and `~/.config`; also pending `.pacnew`/`.pacsave`/`.pacorig` under `/etc` (unreadable folders are counted, never read as clean), foreign packages that need a rebuild (stale python, perl or ruby version folders, and missing libraries read with `readelf -d`, never `ldd`, which runs the file's own loader), files under `/usr` and `/opt` no package owns (never selected for removal), on Debian and Ubuntu `apt-get -s autoremove`, packages left as `rc` (configuration only, `sudo apt purge`) and `.dpkg-dist`/`.dpkg-new`/`.dpkg-old`/`.ucf-*` files under `/etc`, and broken links in the home folder (bounded, caches, Trash, Steam, Wine prefixes, browser profiles and venvs skipped). Unused Flatpak runtimes belong to `clean`: `flatpak uninstall --user --unused` without sudo; the system installation is only reported with `sudo flatpak uninstall --system --unused`, since under sudo flatpak may not see the user's per-user apps.
