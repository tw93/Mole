# `mo clean`

Developer and toolchain caches in `lib/clean/dev.sh` also follow `.claude/rules/clean-dev.md`.

## Target policy

- **A new cleanup target needs measured value and an explicit non-target list.** State bytes actually reclaimable on a real app version, not just the target's total footprint; name sibling directories excluded as user data and prove protection covers every reachable cleanup path. "It looks like a cache" is not evidence, and zero measured value stays out of scope. An encrypted or opaque index cannot prove a directory is unreferenced, so exclude it.
- **Folders a tool runs from or keeps the user's downloads in are not caches, whatever their parent is called.** Playwright (`ms-playwright*`), Camoufox and Cypress under `~/Library/Caches` and Puppeteer's `~/.cache/puppeteer` hold the browser or test runner the tool launches (#1400, #1941, #1945), so `should_protect_path` keeps them and no row targets them; model stores under `~/Library/Caches` (llama.cpp, Buzz) are in `SAFETY_WHITELIST_PATTERNS`, because the generic sweep takes whole children. Before adding a row or extending a sweep, check the folder's owner for the same shape. Locked by `should_protect_path applies high-risk cleanup denylist`, `clean_browsers calls expected cache paths` and `the user cache sweep keeps Buzz models and plugins even with a custom whitelist`.
- **Owner-command rule.** A third-party owner command is still a deletion sink: the supported release must expose every mutated root machine-readably, dry-run and real mode must share one candidate plan, downstream traversal must enforce no-follow physical containment, and partial failures must be observable. Selective prune and dependency-store GC additionally require one lock or generation protocol across the complete mutation. A documented whole-cache reset may omit a shared lock only when the root contains no authored, session, installed, or toolchain state and interruption is equivalent to an ordinary cache miss. Unless the owner explicitly guarantees safe same-machine concurrent use, rebind a tri-state owner-process guard at the command boundary. Mole still validates and whitelists lexical and physical roots, rebinds their identities at the sink, and never falls back to direct deletion.
  - The owner command's status sets the scope of a stop: a signal cancels the run, a timeout (124) skips that one command and is logged, and any other nonzero exit is that tool's ordinary failure. Owners can exit with errno-derived codes above 127 (npm returns 243), so the shell-run owners (`clean_tool_cache`, bun, `simctl`, `brew cleanup`, `tart prune`) cancel only on `mole_rc_signal`, which accepts a status above 127 that `kill -l` names. A `go env` lookup that times out leaves the Go roots unknown and skips the Go caches without cancelling.
  - Locked by `clean_dev_go skips a timed-out owner cleanup without cancelling`, `clean_dev_go skips the Go caches when go env times out and keeps a signal sticky`, `clean_tool_cache treats non-signal high owner statuses as failures (#1695)` and `clean_tool_cache keeps valid signal statuses sticky (#1695)` in `tests/clean_dev_caches.bats`, `mole_rc_signal accepts only statuses that name a real signal` in `tests/core_timeout.bats`, and the interrupted-owner cases in `tests/dev_extended.bats`, `tests/clean_misc.bats` and `tests/clean_system_maintenance.bats`.
- Do not clean tiny macOS UI state just because it is rebuildable. Wallpaper previews, preference thumbnails, and similar cover/state caches can create visible blank or cloud-download UI while reclaiming only a few MB; keep them unless there is strong user value and a regression test.
- `mo clean` empties the whole `~/.Trash` by default (maintainer decision, 2026-10-10). Users who want to keep it tick the `Trash` row in `mo clean --whitelist`, which `clean_trash` honors before anything else; README says so in every language. Do not add a first-run prompt, a keep-Trash flag, or an age window: feedback is split (#163 and #859 want it kept, #362, #392 and #1517 want it fully emptied), and the switch already persists. A retention window needs real user samples from a read-only ctime probe first.
- Homebrew cleanup must be preview-first. Show the exact `brew autoremove` candidates before removal, preserve dry-run behavior, and keep tests on mocked `brew`; do not let a cleanup path execute real package-manager removals in verification.
- Remaining-byte review totals measure actual survivors after cleanup. A zero `safe_clean` result can still mean a protected or unwritable target was kept; dry-run output must not claim a final retained size. Hidden result rows must not call `note_activity`. Locked by `tests/clean_dev_caches.bats` and `tests/clean_hints.bats`.

## Orchestration (`bin/clean.sh`)

- `bin/clean.sh` owns clean command orchestration, section output, and safe cleanup execution. Run `MOLE_TEST_NO_AUTH=1 bats tests/clean_core.bats tests/clean_apps.bats tests/cli.bats tests/clean_summary_cancel.bats tests/clean_developer_state.bats`.
- Section output follows one fixed rhythm: title, then loading state, then content, then one trailing blank line, for every section. When touching any step of it, re-run the command and read the whole rendered output (column alignment, block spacing, icon consistency) instead of patching the one step that was reported.
- **Rows report what Mole did, once.** A `safe_clean` row that measured 0B still removes and counts its items but prints nothing, unless a sizing timeout made the 0B unknown; roots that share a label clean in one call so per-profile caches read as one row; Large files skips the DerivedData row once developer tools covered every project (`_MOLE_DERIVED_DATA_COVERED`); counts go through `mole_count_label` (`1 item`). The summary box holds two lines: `Removed: X · N items` plus the free-space line, or `Potential space: X · N items` plus the file list. Locked by `safe_clean removes a 0B target without printing a row for it` (`tests/clean_core.bats`), `clean_wechat_container_caches cleans every web profile in one row per cache kind` and `large files leaves out DerivedData that developer tools already covered`.
- **Review rows go through `mole_review_row`: `⊙ label · value · fact`.** On a terminal the label is an OSC 8 link to the path, so the row carries no path or command field; plain output keeps the path last. The fact is worked out read-only and bounded (`_large_dir_fact`: simulator count, archive builds and month range, pnpm store versions, project count; version folders besides the default for Rust and NDK) and is dropped, never guessed, when its probe fails. Do not add a command for the user to run where Mole can state the fact itself; two of three suggested commands freed nothing on the maintainer's Mac (2026-10-31). Locked by `large files links each review label to its full path` and `large files names what the simulator and pnpm rows hold` in `tests/clean_user_core.bats`.
- `_safe_clean_impl` skips targets that do not currently exist before expensive policy probes, then filters protected, whitelisted, and compiled-model targets before consulting the dry-run guard or registering previews. Every surviving target is revalidated at its action boundary, so preview and real cleanup keep the same eligible set. A delete guard that refuses only the path it was handed names it in `_MOLE_SAFE_CLEAN_SKIP_PATH`, which skips that target and continues the batch; any other nonzero guard status stops with 75 and a timeout or signal cancels. `safe_clean_guarded skips only the path its guard names and keeps going` in `tests/clean_core.bats` locks it.
- `normalize_paths_for_cleanup` collapses a Gradle DSL path only in the `<version>/groovy-dsl|kotlin-dsl/<hash>` layout, because the `*` in its case glob spans slashes and a deeper directory that merely contains `groovy-dsl` would otherwise widen to its parent.
- **A `declare -f` probe into `bin/` is a shared shim, never a per-file copy.** Asking whether `safe_clean_guarded` or `defer_cleanup_family` exists is asking whether `bin/clean.sh` is loaded: always in production, never in a standalone Bats case. Use `mole_defer_cleanup_family`, or call `safe_clean_guarded` directly and let the test supply it. The audited fallback cap may decrease after consolidation but needs an explicit reason to increase. Do not hoist `_safe_clean_impl` into `lib/core/`; many tests intentionally replace `safe_clean`, and bypassing that seam turns assertions into real deletion attempts under their fixture `HOME`.
- The process-state guard (`mole_clean_process_guard`) and section helpers shared with `lib/core/base.sh` are in `.claude/rules/core.md`.

## User-level cleanup (`lib/clean/user.sh`)

- `lib/clean/user.sh` owns user-level cleanup flows, browser caches, cloud/app support cleanup, device firmware, and Apple Silicon caches. Run `MOLE_TEST_NO_AUTH=1 bats tests/clean_user_core.bats tests/clean_browser_versions.bats tests/clean_app_caches.bats tests/clean_cached_device_firmware.bats tests/clean_misc.bats` when touching this area, or `MOLE_TEST_NO_AUTH=1 ./scripts/test.sh` if behavior crosses sections.
- Chrome / Edge / Brave old-version cleanup is one table-driven helper (`_clean_chromium_old_versions`) plus three thin public wrappers; the wrapper names are the test surface, so keep them. `clean_edge_updater_old_versions` is deliberately NOT part of it: it prunes staged updater payloads strictly older than the installed Edge (falling back to keep-latest by `sort -V` when the installed version is unreadable), has no `Current` symlink, and never escalates to a sudo removal, so folding it in would silently change its semantics.
- Large-files review rows share `_large_candidate_size_kb`: a du exit of 1 means some entry was unreadable and still carries a usable total, while a timeout never does. The E5RT row passes `exact` and drops a status-1 total, because #1631 promised incomplete measurements are never shown as a complete size. Tighten a new row's evidence at that row, not in the shared helper; the compiled-model row once made the helper strict and hid an 11.78GB `Simulator data` row. Locked by `large files keeps a du total that skipped unreadable entries` and `large files skips an E5RT total that missed unreadable entries (#1631)` in `tests/clean_user_core.bats`.
- The fixed rows are measured ahead of the report by a pool of at most four workers under one shared deadline (`_large_prefetch_queue_rows`), and the worktree container search runs beside it; a new fixed row belongs in that list too, or it is measured inline after the pool and adds its full time. `large files queue lists every fixed HOME row the report measures` in `tests/clean_user_core.bats` reads every literal `$HOME` row out of the report source and fails when the queue misses one. The Docker Desktop data row stays queued unconditionally, because whether the report skips it depends on the later `docker system df` probe. That probe runs only on a local engine (`.claude/rules/clean-dev.md`), once, and its row reads `Images 931.5MB, 859.1MB reclaimable`: types and reclaimable figures under 1MB are left out.
- The snapshot rows (`check_large_file_candidates`, and `clean_local_snapshots` with its `tmutil status` probe) run no `tmutil` while any volume without the `local` flag is mounted (`mole_network_volume_mounted` in `lib/clean/snapshots.sh`); the rows are then absent, with no skip line. Every tmutil verb opens each mounted volume, and the Mac app raised "access files on a network volume" from its scan with an SMB share mounted and no Full Disk Access (2026-11-10); the CLI's call would be charged to the terminal the same way (not reproduced on the CLI). The table is `/sbin/mount` with no arguments, which reads the cached `getmntinfo(MNT_NOWAIT)` table and touches no volume (the same flags the Mac app reads with `getfsstat(MNT_NOWAIT)`); the options are taken after the LAST ` (` so a mount point holding parentheses parses, and `autofs` trigger nodes (`/System/Volumes/Data/home`) do not count. An unreadable or unparsable table also skips (report-only rows, so skipping costs nothing; the Mac app fails open there). `clean_time_machine_failed_backups` keeps its `tmutil` calls: a network Time Machine destination is itself such a mount, and skipping would stop that cleanup for every NAS-backup user. Tests stub `_mole_mount_table`. Locked by `mole_network_volume_mounted reads the local flag of every mount table entry`, `clean_local_snapshots runs no tmutil while a network share is mounted` and `large files lists snapshots with only local volumes and runs no tmutil beside a network share` in `tests/clean_system_maintenance.bats`.
- The generic Application Support sweep (`clean_application_support_logs`) skips an app folder whose `SingletonLock` (Chromium and Electron write `<host>-<pid>` there while running) names a live pid or cannot be read, and checks again before each cache folder; it cleared Code Cache and GPUCache under running Docker Desktop, VS Code and T3 Code before. A stale lock left by a crash, and apps with no lock, keep the old behaviour. Locked by `clean_application_support_logs keeps caches of a running Electron app` in `tests/clean_user_core.bats`.
- Browser signing-clone probes must preserve signal statuses through process checks, metadata, open-handle checks, snapshots, and final guards. A timeout keeps the clone; an interrupt stops later candidates and system cleanup stages. Locked by `tests/browser_clones.bats`, where each snapshot guard has its own case except the two uid ownership checks (a differently owned fixture needs root) and the root-prefix check.
- **Leaked automation browsers are identified by a `playwright_chromiumdev_profile` browser root with ppid 1, never by the playwright-cli daemon.** The daemon is spawned detached, so ppid 1 is its normal state for the life of an active session; matching it kills a live session. A profile directory is stale only when `pgrep -f` returns exactly 1; any other status is an unknown state that keeps it. Locked by `tests/clean_automation_browsers.bats`; the story (#1518) is in `.claude/skills/bugs/references/deletion-evidence-and-final-sink.md` section 2.
- Cached firmware cleanup requires an exact-file open-handle probe before sizing and after sizing in preview or at the final `safe_remove` sink. Open or unknown files stay, read-only probe timeouts skip the candidate, and signals cancel later cleanup. Bind the original parent and file identities through the sink, reject symlink ancestors below HOME, and keep backups, partial downloads, and nested iTunes files outside the candidate set. The probe is a point-in-time check, not a restore transaction lock. Locked by the firmware guard cases in `tests/clean_cached_device_firmware.bats`.
- CrashReporter and Cursor Agent log scans propagate signals through their support/app-cache and developer-step callers before later caches or previews start. Ordinary scan failures and read-only timeouts skip that scan and preserve later cleanup. Locked by the support-signal cases in `tests/clean_user_core.bats` and the Cursor scan case in `tests/dev_extended.bats`.
- Log directory cleanup must not expand globs through symlinked roots or ancestors below HOME. Keep `~/Library/Logs/DiagnosticReports` itself, bind root identities before enumeration, and recheck them after sizing and at the final sink. User logs and the standalone DiagnosticReports root share this guard. Office container logs remain blocked by their existing data-protection policy. Locked by `tests/clean_user_core.bats`.
- `validate_external_volume_target` requires a successful `diskutil info -plist` result with boolean `Internal=false` and a nonempty string `BusProtocol` outside the refused network protocols. Failed or timed-out probes, including partial stdout, missing or mistyped fields and malformed plists never authorize cleanup; signals retain their status. Human-readable labels are not evidence. Locked by the `external volume metadata` cases and `validate_external_volume_target refuses internal volumes and an empty answer (#1818)` in `tests/clean_user_core.bats`.
- External-volume cleanup (`mo clean --external`) removes only `.TemporaryItems`, `.DS_Store`, and AppleDouble `._*` metadata; a volume Trash (`<volume>/.Trashes`) is recoverable user data, never an OS-metadata target, and stays pruned from the metadata walk. The `Finder metadata, .DS_Store` whitelist row (`PROTECT_FINDER_METADATA`) covers both scans, so a protected run leaves `._*` files alone. Locked by `external metadata scans preserve system roots in preview and cleanup` and `external cleanup keeps a volume Trash, skips unreadable temporary roots, and protects Finder metadata` in `tests/clean_external.bats`.

## Per-app caches (`lib/clean/app_caches.sh`)

- VS Code extension cleanup (`clean_editor_obsolete_extensions`) accepts only boolean `true` entries in `.obsolete`, never false values or strings.
- `lib/clean/app_caches.sh` owns per-app cache cleanup and the Autodesk Fusion old-bundle pruner. Run `MOLE_TEST_NO_AUTH=1 bats tests/clean_app_caches.bats`.
- Fusion deletes whole bundles, so keep its complete evidence chain: 40-hex directory, exactly one `com.autodesk.fusion360` bundle, an older `CFBundleVersion`, owner rechecks around metadata work, and final identity binding through `safe_remove`. Real mode performs the candidate guard before sizing and again at the sink; dry-run rechecks after sizing because it has no sink. The Finder-alias branch is not exercised under test mode and needs a Fusion-installed Mac. Re-anchor the race tests before reducing any expensive alias resolution; the general lifecycle contract lives in `.claude/skills/bugs/references/deletion-evidence-and-final-sink.md`.

## Application data, services and hints (`lib/clean/apps.sh`, `lib/clean/hints.sh`)

- `lib/clean/apps.sh` owns application-data cleanup, orphan service discovery, and the narrow verified-container-stub exception. `lib/clean/hints.sh` is read-only guidance and must stay bounded, timeout-aware, and non-destructive. Run `MOLE_TEST_NO_AUTH=1 bats tests/clean_apps.bats tests/clean_hints.bats`.
- An app shape the uninstall inventory accepts (a PlayCover launcher alias, through `mole_playcover_alias_target`) must be accepted by `scan_installed_apps` through the same helper: when only the inventory knew it, the clean-side scan failed closed and skipped App leftovers for every PlayCover user (`233c3292`, after `5cc7d1d9` and `66ed80a1`).
- The Claude VM leftover is only a `*.bundle` directly under `Application Support/Claude/vm_bundles`; other bundles below `Application Support/Claude` are not VM evidence. `_orphan_path_is_stale` walks every entry for its 7-day age, at discovery and again at the final sink, because writing `rootfs.img` leaves the directory's mtime alone; a walk that fails or times out keeps the bundle. Locked by `clean_orphaned_app_data treats only vm_bundles entries as the Claude VM`, `is_claude_vm_bundle_orphaned reads the age of the files inside the bundle` and `orphan cleanup guard rechecks the Claude VM age at the final sink` in `tests/clean_apps.bats`.
- Orphaned caches, logs and saved state use the same `_orphan_path_is_stale` walk for their 30-day age, at discovery and at the final sink: a directory's own mtime misses a write to a file already in it. Each walk has the 5-second probe budget and walks in one run share 60 seconds (`ORPHAN_AGE_WALK_BUDGET_SEC`, which sizing and removal do not spend); a tree that cannot finish in time is kept, not cleaned. `-exec /bin/test -x` runs only for a directory this user does not own, has no owner search bit on, or that carries an ACL, because one process per directory took 14.9 seconds on a 7,815-directory cache against 0.85 without it (BSD find, 2026-11-09). Locked by `is_bundle_orphaned reads the age of the files inside the directory` and `orphan cleanup guard rechecks the age of a bundle's files at the final sink`.
- Orphan leftover `mdfind` / size timeouts fail closed for that item and must not cancel later `mo clean` sections. A leftover sink timeout stays sticky. Locked by the `#1584` cases in `tests/clean_apps.bats`.
- System-service orphan scans must parse plist `Program` / `ProgramArguments` values as absolute paths only. Use non-interactive sudo for unreadable root-owned plists when needed, reject PlistBuddy error text as data, and keep CI tests on `/Library/LaunchDaemons` rather than relying on `/Library/PrivilegedHelperTools`; a bare-helper test stubs `_privileged_helper_root_exists`, since GitHub runners have no such folder.
- Treat a launchd plist and its `Program` helper as one cleanup family. A standalone helper-app path under `/Library/PrivilegedHelperTools/*.app/Contents/MacOS/*` stays protected even when an updater temporarily removes the executable leaf; before deleting any direct helper file, re-scan LaunchDaemons and LaunchAgents completely and keep it when a surviving plist still references it or the reference scan is inconclusive.
- A plist whose `Program` helper still exists under `/Library/PrivilegedHelperTools` is asked about its parent app only when the helper id is reverse-DNS (`com|org|net|io`, as the bare-helper pass): a plain file name is no bundle id, so a live KeepAlive cloud-print updater read as orphaned and was offered for removal (Mole Mac field report 2026-10-20). Locked by `clean_orphaned_system_services keeps a live helper whose name is no bundle id` in `tests/clean_apps.bats`.
- A present helper binary is orphaned only when it validates as Developer ID (`_privileged_helper_is_developer_id_signed`, `codesign --verify -R` with Apple's Developer ID requirement), in both the plist pass and the bare-helper pass, where a helper-root `.plist` follows its same-named binary when that binary exists. A user's own helper (clang build, ad-hoc or self-signed, a personal Apple Development certificate) has no parent app to lose; a reverse-DNS name was not enough (Mole Mac field report 2026-11-02, a running `~/bin/lid` daemon offered as orphaned). A Team ID alone is no proof, since development certificates carry one. Unreadable, unverifiable or timed-out checks keep the helper. Locked by `clean_orphaned_system_services keeps a live helper built on this Mac` and `clean_orphaned_system_services lists a bare helper only when it is Developer ID signed`.
- A LaunchAgent plist name (`~/Library/LaunchAgents`, `/Library/LaunchAgents`) claims that bundle id in `scan_installed_apps` only while its job can run (`_mole_launch_agent_job_can_run`, the Mac app's rule): it stops claiming only when the absolute `Program` / `ProgramArguments[0]`, or for `open` and an interpreter (`sh`, `node`, `python3`, `osascript`, `env <cmd>` and the rest) the app or script it runs, is provably gone. Provably gone means absent behind a searchable nearest ancestor, plainly spelled, reached through no link, outside `/Volumes` and the prompting home folders (Desktop, Documents, Downloads, iCloud, CloudStorage, Containers, Group Containers); `open`'s value options (`--stdout`, `--env`, `-u`, ...) and interpreter value options are skipped, inline code and modules judge nothing. Every doubt keeps the claim: an unreadable, malformed or XML-escaped plist, a bare or relative program, and any agent past the medium-probe judging budget. Before this every plist claimed, so a dead agent kept its app's leftovers out of `mo clean`. The judging is plutil `-extract ... xml1` per key, about 14 ms a plist (13 plists in 0.18 s on the maintainer's Mac, 2026-11-11), in the background beside the app scan. Locked by `scan_installed_apps drops the claim of a LaunchAgent whose job provably cannot run` and `scan_installed_apps keeps the claim of a LaunchAgent it cannot prove dead` (each guard red-run by breaking it alone).

## Project caches (`lib/clean/caches.sh`)

- Project-cache discovery's Git index is not deletion authority. Recheck literal tracked content and nested repositories after sizing and at the final sink, including grouped Python caches and standalone cleanup. Discovery's index folds case on both sides and the rechecks use a full-path `:(top,literal,icase)` pathspec from `mole_git_path_spec`, so a cache under a folder renamed only in case is still seen as tracked. Each recheck draws on its own bounds (the Git query on `MOLE_TIMEOUT_MEDIUM_PROBE_SEC` from its own start, the nested-repository walk on `MOLE_TIMEOUT_MEDIUM_PROBE_SEC`), never on a step-wide budget, and each root builds its index on a fresh `MOLE_TIMEOUT_HINT_SCAN_SEC`. Unknown keeps the target; signals cancel. A refusal that concerns only the path it was handed (a symlink, a nested repository, an unknown Git answer) skips that target alone, so one refused `.next/cache` child leaves its siblings to be cleaned. A removal timeout in the Python or standalone route counts one failed removal, and only a signal ends the run. Locked by `tests/clean_system_caches.bats`.

## Whitelist (`lib/manage/whitelist.sh`)

- Whitelist absence must be a confirmed `ENOENT`, never a failed shell `-f` test. Both loaders check ancestors and symlink targets before selecting defaults or the legacy optimize list; inaccessible paths, broken links, non-files and probe failures stop the command. Diagnostics name the inaccessible ancestor when known. Locked by the whitelist loader and entrypoint cases in `tests/manage_whitelist.bats`.
- Both the shared loader and whitelist editor preserve a final nonempty line without a trailing newline. A hand-edited protection must not disappear on load or after editing the list. Locked by the `last protection without a trailing newline` cases in `tests/manage_whitelist.bats`.
- Whitelist inventory rules for package-manager rows are in `.claude/rules/clean-dev.md`.
- Whitelist or management changes: run `MOLE_TEST_NO_AUTH=1 bats tests/manage_whitelist.bats tests/manage_sudo.bats`.
