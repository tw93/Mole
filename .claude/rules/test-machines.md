# Test machines

- Omarchy: the Try Omarchy VM on the ThinkPad (lease `thinkpad`), reached from the Mac with `ssh -F ~/.config/mole-omarchy/config mole-omarchy` through the ThinkPad hop. The guest runs a user-level sshd (systemd user unit `mole-sshd`, port 2222, key only); the host-side forward `127.0.0.1:2222` is a runtime QMP `hostfwd_add n0 tcp:127.0.0.1:2222-:2222` and must be re-sent after every VM restart. Off the home LAN, a UU Remote port mapping on the ThinkPad (local 2222 to its `127.0.0.1:2222`) replaces the hop: add `-o ProxyCommand=none` and the same known_hosts entry matches. The guest's own traffic leaves through QEMU, not the host's Clash, and github.com release downloads get reset on that network (2026-11-02); run downloads as `~/.local/bin/ghproxy <cmd>`, which sets the proxy for that one command to the host's Clash at `10.0.2.2:7890` and runs direct when the port is closed (public `install.sh` plus `mo update` through it: 4 s). Never export a proxy shell-wide or touch the host's Clash settings. `~/.bashrc` returns early for non-interactive shells, so ssh commands get neither its PATH nor its functions: call `~/.local/bin/...` by path. No sudo password is available there: tests run as the desktop user, bats and shellcheck 0.11 live in `~/.local/bin` and Go in `~/.local/opt/go` (PATH in `.bashrc`, GOPROXY goproxy.cn), so the full gate runs there natively. Password flows are tested in the devbox instead, with a throwaway password and sudoers entry for its user `mole`, both removed afterwards. The guest locale is Chinese, which is the point: parsing must survive it. Its root is ext4 and `/tmp` is tmpfs; the devbox's overlay sits on btrfs. Go fixtures in `t.TempDir()` land on `/tmp` on both, where directories take no blocks, so a size that depends on a directory's own block only shows on the GitHub runner (ext4). Interactive screens are driven with tmux (`send-keys`, `capture-pane`), never over `ssh -tt`.
- Real btrfs + snapper (no test machine has a btrfs root): a throwaway second QEMU on the ThinkPad (lease `thinkpad`) boots the Try Omarchy kernel with its `disk.raw` as `snapshot=on` (writes discarded, the real VM untouched), a fresh raw disk, `init=/bin/bash` on a TCP serial and a hostfwd to a root sshd with the Omarchy key. There, `pacman -S btrfs-progs snapper`, build `@`, `@home`, `@log` (and optionally `@pkg`), copy the system in, chroot, apply Omarchy's `install/config/snapper.sh` steps and a throwaway NOPASSWD sudoers entry, and run `mo` as the desktop user. Launch QEMU through a one-off scheduled task (an ssh session's children die with it), stop it by PID, delete the task, disk and tunnel, release the lease. Test files on btrfs need `cp --reflink=never`, or the copies share extents and freeing them proves nothing. Verified 2026-11-02: `/.snapshots` is root 0750, the config 0644; 231 MB of old packages freed 0 MiB until the snapshot was deleted, then 220 MiB.
- End-to-end use on the devbox (2026-11-02 for 0.3.0): `scripts/build-release.sh` on the Mac, copy the x86_64 archive, `SHA256SUMS.txt` and `install.sh` into the container, install as `mole` with `install.sh --archive … --sums …`, then run each command the way a user would, interactive screens in a tmux session (`send-keys`, `capture-pane`), with small fixtures (`head -c` blobs in caches, a project with old `node_modules` and `target`). For the sudo prompt, give `mole` a throwaway password and an `/etc/sudoers.d` entry, try wrong, right, Space and ESC, then delete the entry, `passwd -d` and `passwd -l` the account (its original state), `mo remove --yes` and delete the fixtures. Debian has no pacman or Flatpak apps, so uninstall is not covered there; `update` needs GitHub, which the devbox reaches only through the Mac's proxy on the home LAN.
