# `mo uninstall`

Uninstall changes at minimum: run `MOLE_TEST_NO_AUTH=1 bats tests/uninstall.bats tests/uninstall_remove_file_list.bats`, plus the hotspot commands below.

## App protection (`lib/core/app_protection.sh`)

- `lib/core/app_protection.sh` owns uninstall/data/path protection policy and bundle matching; `lib/core/app_protection_data.sh` owns the protected app category lists. Run `MOLE_TEST_NO_AUTH=1 bats tests/uninstall_safety.bats tests/uninstall_naming_variants.bats tests/bundle_resolver.bats`.
- Bundle protection matching is case-sensitive glob (`bundle_matches_pattern`; the hot clean-mode checks in `should_protect_path` and `should_protect_data` test the whole list at once through `_mole_matches_protected_glob` against an `@(a|b|...)` alternation built at load, so a list entry must not contain `|`, `(` or `)`; quoting the right-hand side of either test silently turns every wildcard protection into an exact match), and macOS system bundles report inconsistent casing across releases (macOS 26 ships `com.apple.bootcampassistant` alongside the older `com.apple.BootCampAssistant`).
- When the monthly bundle drift audit reports gaps, add the exact IDs as the audit printed them, and check the runtime blanket `com.apple.*` guard before rating the gap's severity. The audit workflow's issue path requires the `bundle-drift` label to exist in the repo.
- In uninstall mode `should_protect_path` matches the `APPLE_UNINSTALLABLE_APPS` globs before the `SYSTEM_CRITICAL_BUNDLES` rows; the shipped lists do not overlap, so `uninstall mode matches the Apple uninstallable globs before the critical rows` in `tests/uninstall_safety.bats` uses a fixture critical row to make the order observable.

## Inventory and display names (`bin/uninstall.sh`)

- A new app shape the inventory accepts (a PlayCover launcher alias through `mole_playcover_alias_target`) must also be accepted by `scan_installed_apps` in `lib/clean/apps.sh` through the same helper, or Clean skips that app's leftovers (`.claude/rules/clean.md`).
- `bin/uninstall.sh` owns uninstall command orchestration, app inventory, metadata refresh, and list/json output. Run `MOLE_TEST_NO_AUTH=1 bats tests/uninstall.bats tests/uninstall_scan_bash32.bats`.
- Warm-cache rows must still resolve live app eligibility. The first inventory snapshot belongs only to the completed list that produced it; later menu checks enumerate again. Batched `STAT_BSD` probes preserve literal path tabs and broken Info.plist symlinks, and discard partial batch output before fallback. Allocate parallel result files atomically or inside a private mktemp directory, drain workers before scratch removal, and discard inventory sidecars from list and by-name consumers too. The final exit handler must reclaim registered scratch, including interrupted allocations.
- Never take the display name from `mdls -name kMDItemDisplayName`, which returns the bundle's on-disk file name (#1520; story in `.claude/skills/bugs/references/shell-and-test-pitfalls.md` section 7). The name Finder shows lives in `Contents/Resources/<lang>.lproj/InfoPlist.strings`, read in `AppleLanguages` order, stopping at the first preferred language the bundle localizes at all so an English-preferring Mac never inherits another language's override. Validate any change here against `NSFileManager.displayName` over every installed app; the one difference that cannot be closed from the bundle is a LaunchServices regional rename such as TV to Videos. The resolved name is cached, so a resolution change also bumps `MOLE_UNINSTALL_META_CACHE_FILE`.
- No shell-side directory size cache (the rule and its APFS mtime reason are in `.claude/rules/core.md`). Uninstall preview workers measure every invocation afresh, publish rows in review order, preserve timeout/signal status, and drain before removing their private result directory. The discovery plan carries only the current bundle size until personal-data review calculates the selected leftovers; kept personal data is listed without a size probe. Reuse that invocation's bundle size within its confirmation screen, never across invocations.
- **Confirmation needs a real terminal unless a test flag is set.** A failed or empty `read` is not Enter: the batch preview returns 3 when stdin is not a TTY (or the single-key read fails) under production, and the batch converts that to exit 1; only `MOLE_TEST_MODE` may drive the prompt through a pipe, because `MOLE_TEST_NO_AUTH` is also used for real-machine repro. A dry run has nothing to confirm, so without a terminal it prints the plan, says nothing was removed and exits 0 (preview status 4). Locked by `real uninstall preview refuses /dev/null without a terminal`, `real uninstall preview refuses a piped n without a terminal` and `dry-run uninstall preview without a terminal ends cleanly after the plan` in `tests/uninstall_review.bats`.
- **By-name uninstall asks once.** `mo uninstall <name>` prints the matched list, then hands off to `batch_uninstall_applications`, whose preview is the single confirmation; the old pre-scan `[y/N]` prompt is gone because it ran before sizing and leftover discovery and could not review anything. Locked by `by-name uninstall shows the batch preview once instead of a pre-scan prompt` in `tests/uninstall.bats`.
- **Display names are sanitized at render sites.** The by-name matched list and `format_app_display` in `lib/ui/app_selector.sh` pass names through `mole_terminal_safe_text` so bundle-supplied terminal control bytes cannot reach the terminal; stored names, `apps_data`, filtering and matching stay byte-identical. Locked by `by-name matched list renders control characters as placeholders` and `app selector renders control characters in display names inert` in `tests/uninstall.bats`. The batch preview, spinner and completion summaries render through `_uninstall_display_text` in `lib/uninstall/batch.sh`; locked by `batch preview display names are terminal-safe` and `batch preview and summaries render app names through the terminal-safe helper` in `tests/uninstall.bats`.

## Leftovers and ownership

- Uninstall leftover expansion must stay exact and boring: bundle ID or app-name variants only, reject generic/common words, keep short-name floors, skip broad locations like `Preferences/ByHost`, and only remove helper remnants after the parent app is confirmed gone and protected-path checks pass.
- Uninstall preserves the shared `~/Library/Unity` and `~/Library/Application Support/Epic` roots, and never offers `~/Library/Application Support/Steam` or anything inside it: that folder holds the whole `steamapps` game library, and Mole CLI (Windows) refuses Steam libraries after a user lost one (`3c8a6fee` on `windows`). `mo clean` still takes its exact cache leaves. Locked by `uninstall never offers the Steam library root or anything inside it` in `tests/uninstall_safety.bats`, `remove_file_list refuses the Steam library root and its contents` and `batch uninstall of Steam keeps the game library even with every data row selected`.
- `--with-data` preselects every personal row except the holdbacks in `_uninstall_data_preselect_holdback` (`lib/uninstall/review.sh`): browser profile roots, `~/Library/Group Containers`, and game or ROM libraries kept inside one app's data root (`Application Support/CrossOver` and the Whisky container hold bottles of installed Windows games, `Application Support/OpenEmu`, `Dolphin`, `PCSX2`, `RetroArch`, `PrismLauncher`, `Minecraft`, `Citra`, `Cemu`, `Ryujinx`, `PPSSPP`, `RPCS3`, `MultiMC`, and `ATLauncher` hold ROMs, worlds or saves). They stay listed so `D` can still select them; unlike Steam they are not refused, because the user asked to remove that app's data. Locked by `--with-data holds back CrossOver, Whisky and OpenEmu game libraries` in `tests/uninstall_review.bats`.
- IDE product-prefix scans accept only the exact product or a glued four-digit year plus dotted version; similarly named tools and backup folders stay. Locked by `uninstall preserves shared engine roots while keeping exact app caches` and `versioned IDE leftovers exclude similarly named products and backups` in `tests/uninstall_safety.bats`.
- Framework leftovers claim exact leaves only: `<bundle-id>.ShipIt`, exact app-name updater folders, Crashlytics/Bugsnag bundle leaves and SentryCrash/KSCrash app-name leaves. Never claim their shared parent or use common runtime names such as Electron. Do not expand preferences to `<bundle-id>.*.plist`: a dot boundary does not distinguish another product from a subordinate preference domain.
- JetBrains selectors come from the literal `JVMOptions.Properties["idea.paths.selector"]` Info.plist key. Claim only the exact validated product/version leaf. Same-selector or unreadable-selector survivors retain the family even when bundle IDs and display names differ; classify JetBrains IDs case-insensitively at discovery, preview, execution and sibling probes; carry the previewed selector in the app plan, reject changed or unreadable metadata before teardown, and retain the verified selector across the app move.
- UUID containers require an exact `MCMMetadataIdentifier`, rechecked after sizing and by the final individual Trash/permanent sink; never send them through the generic Trash batch. NativeMessaging manifests require a regular bounded JSON file whose path points inside the selected app, with physical containment checked while it exists. Reuse the identity/hash/app-absence sink contract after the bundle moves; do not claim hosts installed elsewhere. Locks are the UUID and native-manifest tests in `tests/uninstall_safety.bats` and `tests/uninstall_remove_file_list.bats`.
- **Sibling guard.** Any new uninstall teardown path (launch services, login items, cask zap, helper bootout) must route through the shared-bundle-id sibling guard, covering `/Volumes` copies, inverse-name, and shared-identity variants, with a Bats regression per variant.
  - A symlink used as an application scan root is unknown, not proof of absence: default `find` does not traverse it. Keep shared leftovers in preview and execution, without expanding traversal with `find -L`; `tests/uninstall.bats` covers physical positive/negative controls and the final recheck.
  - Volume discovery excludes the exact `com.apple.TimeMachine.localsnapshots` directory only when both it and the volume root are real root-owned directories on the same device, and a mount point that the mount table lists as smbfs, nfs, afpfs or webdav and that a bounded lstat reports as ENOENT (a share whose server is gone, such as a stopped Parallels VM's drive); a mounted disk with that name, unverified metadata, an unknown mount table, a slow or reconnecting share, any other lstat error, an unlistable volumes root, and every other unreadable volume remain in scope.
  - find fails on an unresolvable entry before `-prune` is evaluated, so each remaining volume is scanned one level down as its own start point, which keeps the original depth-two candidates. The preview and final recheck share this policy.
- **Family ownership.** Uninstall ownership includes independent dot-continuation bundle IDs and channel-stripped same-name products, not only identical IDs. Keep the whole leftover family when a survivor exists or the inventory is incomplete; embedded helpers still belong to their host.
  - Recheck after the app move, for every plan, including replacement at the original path (that test needs no sibling scan, so it also covers plans demoted to an unknown id and ids that are not reverse-DNS), and carry refusal through defaults, ByHost and helper bootout. The recheck runs even when the leftover list is empty, because its status gates those side effects.
  - A retained family is recorded by cause (`shared-owner`, `owner-unknown`, `app-reappeared`) and printed once, never as protected, and a dry run lists kept rows through the same reason filter as a real run. A retained full container is not an empty system stub and must not count as reclaimed space.
  - Locked by the family-owner and post-move cases in `tests/uninstall_safety.bats` (including `a retained leftover family names its cause once instead of per path`) and `remove_file_list keeps leftovers when the app returns, whatever the plan's bundle id` in `tests/uninstall_remove_file_list.bats`.

## Batch execution and Homebrew (`lib/uninstall/batch.sh`)

- `lib/uninstall/batch.sh` owns batch uninstall execution, the shared-bundle-id sibling guard, launch service and login item teardown, and brew cask removal routing. Run `MOLE_TEST_NO_AUTH=1 bats tests/uninstall.bats tests/brew_uninstall.bats tests/uninstall_remove_file_list.bats tests/uninstall_safety.bats`.
- `uninstall_bundles_share_remnants` runs once per installed app in every sibling scan, three scans per selected app. Ordinary ID/name matching stays fork-free (`mole_ascii_lowercase`, `_uninstall_strip_version_suffix_into`, no `tr`); only two JetBrains IDs trigger bounded selector probes, and unknown selectors retain the family; `sibling matching folds case in-process instead of forking per candidate` in `tests/uninstall_safety.bats` locks it.
- Homebrew Caskroom and installed-list snapshots are complete, bounded, and scoped only to one inspection pass; discard them before confirmation, keep exact ownership checks, and always probe installed state afresh after removal.
- A failed third-party `brew info` lookup may use Caskroom ownership only when the unique installed cask has an app symlink pointing to the exact selected app, rechecked after the lookup. A matching basename or copied bundle is insufficient; timeout and signal failures still abort. Locked by the `#1558` cases in `tests/brew_uninstall.bats`.
- **An ownership check that refuses must name the app it could not classify and send the user to `brew info --cask`, never `brew list --cask`.** A cask brew cannot parse still lists cleanly under `brew list --cask`, so that listing diagnoses nothing and leaves a multi-app batch with no way to tell which selection aborted. Locked by the `#1579` case in `tests/uninstall.bats`.
- The lsof-mode memo ordering (`ensure_sudo_session` before `_batch_execute_removals`) is a Critical Safety Rule in `AGENTS.md`.
