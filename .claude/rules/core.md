# Core helpers: deletion funnel, sizing, section helpers, UI

## `lib/core/file_ops.sh` and `lib/core/base.sh`

- `lib/core/file_ops.sh` owns the deletion funnel, Trash/permanent routing, operation-log outcomes, size accounting, and last-mile path validation. `lib/core/base.sh` owns shared shell primitives and source-order-sensitive section helpers. Keep policy in the existing protection helpers rather than adding a second delete path. Run `MOLE_TEST_NO_AUTH=1 bats tests/file_ops_mole_delete.bats tests/file_ops_size.bats tests/file_ops_safe_remove_symlink.bats tests/user_file_ops.bats tests/core_safe_functions.bats tests/history.bats`.
- Both find/delete helpers preserve signal statuses in the clean cancellation marker, including scan, sizing, preview and privileged preflight failures; a prior cancellation stops them before further work. Read-only scan or sizing timeouts stay local and never set that marker. A signal from `validate_path_for_deletion` must stop the privileged scan loop and discard its accumulated removal batch, not become an ordinary refusal via `if ! ...; then continue`; a validator timeout still skips only its target. Locked by the `preserves scan signals`, `preserves dry-run sizing signals`, `read-only timeouts remain local`, `preserves preview validation signals`, `stops before work after sticky cancellation`, `stops accumulated batches on validation signals` and `validation timeout skips only its target` cases in `tests/core_safe_functions.bats`.
- `validate_path_for_deletion` refuses every path when `should_protect_path` is not defined (a caller that sourced `file_ops.sh` without `app_protection.sh`), logging `protection rules not loaded`; it never skips the protection check. Every product entrypoint loads both through `common.sh`. Locked by `validate_path_for_deletion refuses every path when protection rules are not loaded` and `safe_find_delete keeps files when app protection is not loaded` in `tests/core_safe_functions.bats`.
- **A stored timestamp from the future is expired, not fresh.** A freshness or throttle window (`now - stamp < ttl`, `find -mmin -N`) accepts a negative age, so after a clock correction a cache or a daily stamp stays valid until the clock catches up and the work it gates is skipped. Cache and throttle checks treat a negative age as expired; an age check that decides whether to delete or list an old item keeps a future-dated one, the safe direction. Locked by `brew_cleanup_ran_recently treats a stamp from the future as expired` in `tests/clean_system_maintenance.bats`, `Darwin temp root prune lists again when its stamp is from the future` in `tests/user_file_ops.bats`, `cached app metadata stamped in the future is refreshed, a recent stamp is not` and `a receipt cache stamped in the future is rebuilt, a recent one answers` in `tests/uninstall_scan_bash32.bats`, and `TestStampWithinTreatsFutureStampAsExpired` in `cmd/analyze/cache_clock_test.go`.
- A test-only environment seam that chooses a cleanup root (the Xcode documentation, CoreSimulator and XCTestDevices roots, the Chrome, Edge and Brave bundle lists, the external volumes root) is read through `mole_test_path_override`, which honors it only under `MOLE_TEST_MODE` / `MOLE_TEST_NO_AUTH`. Locked by `test-only cleanup root overrides are read only through the test-mode guard` in `tests/dev_extended.bats`, which fails on any direct expansion of a listed seam; add a new seam to that list.
- Trash batches may share stable invoking-user values, never destination ownership/mode or live source evidence. Keep operation and deletion logs synchronous; existing writable logs can skip repeated setup, but a missing log must be recreated. Shared nested-path filtering is literal and must keep parent coverage across prefix siblings; Gradle target normalization belongs only to clean.
- Direct Trash moves, privileged staging moves, staging permission/ownership handoff and final user moves each use `run_with_timeout` with the existing disk-operation timeout. This bounds each command, not the whole uninstall phase. Keep identity/ownership checks immediately before the source move, preserve a staged payload on timeout and stop later candidates without losing the completed-path ledger. Never re-enter a privileged payload operation after the stage is handed to the user. Regression tests must reach the real mover with bounded fixture executables; a batch mock that adds its own timeout proves only status propagation. Locked by the `real direct Trash sink` cases in `tests/uninstall_timeout.bats` and `real privileged Trash sink` cases in `tests/file_ops_mole_delete.bats`.
- **A cleanup total counts readable bytes, and only a timeout makes it a lower bound.** A folder Mole cannot list it cannot remove either, so cleanup sizing retains readable-file totals. `get_path_size_kb` still provides the `readable` mode for callers using `du`; uninstall keeps its strict default (#1404). Clean's `get_cleanup_path_size_kb` and its bulk path share `_cleanup_path_sizes_kb`: allocated file blocks, internal hardlinks counted once only when every link is inside that candidate, and uncompressed APFS private bytes where supported. Symlinks are not followed, directory metadata is excluded, compressed or unsupported private-size probes use allocated bytes, and timed-out bulk results are discarded. Separate candidates deliberately do not claim external hardlink blocks even when both are selected. Sparse files and fully shared clones must not report their logical lengths as freed; real fixtures in `tests/file_ops_size.bats` lock these cases. Before this, six unavailable simulators holding 7.73GB were counted as 0 and the run printed `At least`, which read as a timeout that never happened. `mole_item_size_continues` marks the total partial only for a real timeout, a timeout names its path in the debug log, and the partial total prints as `3.27GB+`, the same form as the Build artifacts hint. Locked by `cleanup sizing counts the readable bytes of a folder with an unlistable child`, `only a sizing timeout marks the cleanup total as a lower bound` and `a sizing timeout names the item in the debug log` in `tests/file_ops_size.bats`.
- **Temp-root pruning takes only names Mole creates, in roots it owns.** `prune_stale_mole_temp_files` empties only `~/.cache/mole/tmp`; `prune_stale_mole_tmpdir_leftovers` runs only when the resolved root is the per-user Darwin temp root (`getconf DARWIN_USER_TEMP_DIR`), never `/tmp` or a TMPDIR set to a user folder, and takes `mole.registry.<digits>` whose pid is absent from one `ps` listing plus `mole.` and six letters or digits as a one-link file or an empty folder, each a day old, minus any name a registry of a still-running pid lists (a run left open overnight still owns its entries). A failing or empty `ps`, or an incomplete read of any live registry, returns quietly with nothing removed; a successfully read registry with no matching temp names is still valid. Locked by `Darwin temp prune retains every candidate when a live registry cannot be read` in `tests/user_file_ops.bats`. Under `set -e` an unguarded `$(ps …)` would end every `mo` command at startup. Like the cache-root prune, this housekeeping of Mole's own scratch runs in dry runs too and writes no operations.log row. The first run on a long-lived root meets tens of thousands of entries (25,412 on 2026-10-27), so filtering stays inside `find` and one `grep -vxF` set difference, not a per-entry Bash loop or probe (23k fixtures: 5.6s looped, under 3s now, 0.08s once clean). Listing the root is the remaining cost and every `mo` command pays it before its first line: a long-lived root held 126,196 entries on 2026-10-31, and four listings per run made `mo --version` take 1.89s. So the root is listed once per run and later checks take only the names that listing matched, and a complete pass leaves `mole.prune-stamp` there so the next listing waits a day (0.54s on the first run of a day, 0.15s after); a failed `ps`, an unreadable live registry or a failed listing leaves no stamp. Locked by `Darwin temp root prune lists the root once a day and only after a complete pass`. Mole Mac's `TemporaryRootLeftoverPolicy` holds the same contract; change both together. Locked by `Darwin temp root prune takes only stale Mole registries and temp entries` and `Darwin temp root prune runs from temp root setup and keeps everything when ps fails` in `tests/user_file_ops.bats`.
- **Do not add a shell-side directory size cache.** APFS does not propagate mtime up the tree, so a parent directory's mtime is unchanged when a descendant grows or shrinks and the cache hands the user a stale reclaimable number. Measure every time; `get_path_size_kb` is already timeout-bounded. The uninstall preview side of this rule is in `.claude/rules/uninstall.md`.
- `start_section` / `end_section` have three intentionally different implementations in `lib/core/base.sh`, `bin/clean.sh`, and `bin/purge.sh`; `note_activity` has two, since `bin/clean.sh` uses the one in `lib/core/base.sh`. Source order decides which one wins, and the wording, color, and dry-run export semantics differ on purpose. Read the cross-reference comment in `lib/core/base.sh` before changing any of them.
- `mole_pgrep_any` joins the patterns of each selector with `|` into one `pgrep -x` and one `pgrep -f`, because pgrep reads every pattern as an extended regex and `-x` anchors the whole alternation; a pgrep per name made the six-name Xcode and CoreSimulator guards cost about 260ms per DerivedData project and simulator item, against about 50ms now. A failed joined probe is unknown (2) even if a later pattern might have matched. Probes that need the matched name (`_coresimulator_cache_process_running`) resolve it with one `pgrep -lx` only after a match. Locked by `Xcode and CoreSimulator process probes each run one pgrep` in `tests/core_common.bats`.
- **`mole_clean_process_guard` in `lib/core/base.sh` is the only translator of the probe tri-state** (`0` running, `1` not, `2` could not tell). State `2` denies; a copy that folds it into "not running" deletes a live app's files while every other copy still reads correctly in review. Compound guards call it for the process question and add their own evidence after; eligibility goes through `mole_cleanup_targets_exist` (predicate list must match `_safe_clean_impl`'s), refusals through `mole_report_guard_stop`. Locked by `mole_clean_process_guard denies on an unknown process state` and `cleanup delete guards do not re-implement the process-state translation`. Left open-coded on purpose: the scan-stage `state -eq 2` blocks pick per-section wording, and the Codex open-file probe inverts the contract.
- Named Application Support caches use `mole_safe_clean_app_cache` with an exact app name. It escapes the name for process and bundle-path probes and shares the existing `_dev_safe_clean_process_guarded` callback in `base.sh`; keep the latter's dynamic leaf binding for compound developer guards. Recheck after sizing and through `safe_remove`'s final hook, retaining running or unknown owners. Chain an existing final hook first, then check the owner so slow outer guards cannot stale the evidence; restore the caller's hook on return. Capture an ordinary leaf's parent/target identity before the post-size probe and reuse it at the final sink, preserving compound probes' existing bindings. Never authorize a replacement by refreshing the snapshot after a probe. The real-sink `cache final sink` tests lock running/unknown/idle, outer refusal, and cancellation. Do not substitute a shared executable name such as Electron. Locked by the `named Application Support caches` and `named app cache guard` tests in `tests/clean_app_caches.bats`.

## `lib/ui/menu_paginated.sh` and `lib/core/ui.sh`

- `lib/ui/menu_paginated.sh` owns the shared Bash 3.2-compatible selection UI and terminal restoration. Preserve trap chaining, TTY restoration, and empty-selection behavior. Run `MOLE_TEST_NO_AUTH=1 bats tests/menu_trap_restore.bats tests/uninstall.bats`.
- Menu controls prefer one line. When space is tight, hide page, navigation, order, select-all, sort and search hints in that order, keeping selection, confirmation and cancel/clear visible. Search entry keeps `Enter Apply` and `Esc Clear`, hiding `Ctrl+U Clear` before `Backspace`. Hidden keys remain active; wrap only when the core controls themselves do not fit. Count their ASCII and single-cell arrows as UTF-8 characters even under `LC_ALL=C`, and derive page capacity from the rendered footer's actual row count. Do not split selection and browsing controls unconditionally or reserve guessed footer rows. Locked by `menu controls hide secondary hints before wrapping and reserve their actual rows` in `tests/menu_trap_restore.bats`.
- `lib/core/ui.sh` owns shared loading frames and inline progress updates. Keep `mo_load_spinner_frames` as the frame loader for clean, purge, and uninstall; preserve complete UTF-8 frames under `LC_ALL=C` and update a live spinner's text without restarting it. Keep the centered two-column, two-row frames in sync with `cmd/analyze/constants.go`; terminal line-height should not turn the loading mark into a tall rectangle. Run `MOLE_TEST_NO_AUTH=1 bats tests/core_common.bats tests/clean_core.bats`; the rendering contract lives in `.claude/skills/bugs/references/state-accounting-and-progress.md`.
- Under Bash 3.2, `drain_pending_input` flushes the whole terminal queue through `/usr/bin/perl` (never a PATH `perl`) and returns without draining a terminal when Perl fails, rather than blocking a second per key; the paginated menu skips it only after search text keys (`CHAR:*`, `SPACE`, `DELETE`), so a pasted term survives while a partly decoded escape tail is still flushed. Locked by `tests/menu_search_pty.py` and the drain cases in `tests/core_common.bats`.
- The ESC timeout rule in `AGENTS.md` (Critical Safety Rules) guards `read_key`: `read_key` ESC decoding is pinned only for piped sequences by `tests/core_common.bats`, and no test pins the timing of its follow-up byte read.
