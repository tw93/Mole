# Windows CLI development pitfalls

Read only the section matching the change. [AGENTS.md](../AGENTS.md) and the area rules in `.claude/rules/` own current safety and compatibility policy; this reference explains verified failure mechanisms from the October 2026 Windows review. [The development record](development-record.md) holds delivery evidence.

## PowerShell path and Git probes

Windows PowerShell 5.1 can return no item for a missing `.git` path without the expected exception, including under bracket-containing paths. Absence of an exception is not proof of existence. The purge ancestor probe uses `File.GetAttributes` and classifies only file/path-not-found errors as missing; other failures retain the candidate. Read its current implementation in [bin/purge.ps1](../bin/purge.ps1) before changing the probe.

Git for Windows rejects `GIT_CONFIG_GLOBAL=NUL` in the tested configuration; the isolated purge process uses `/dev/null`. Preserve its Git environment isolation, literal case-insensitive pathspecs and explicit UTF-8 output decoding. Test a tracked artifact and an eligible untracked artifact under the same bracket-containing path. A test that only expects zero candidates can pass because discovery is entirely broken. [PurgeBoundary.Tests.ps1](../tests/PurgeBoundary.Tests.ps1) includes these controls, Unicode paths and inherited index/pathspec overrides.

## PowerShell host selection

PowerShell 7 implements `Get-WmiObject` through implicit remoting into Windows PowerShell, so the call starts `powershell.exe`; when policy blocks that executable, the cmdlet fails even though `pwsh` itself runs. Use `Get-CimInstance` in runtime scripts. `mo.exe` prefers Windows PowerShell and falls back to `pwsh.exe` only when a host cannot be started; retrying after a host starts could run a deletion command twice. PowerShell 7 also throws "The handle is invalid" when `Clear-Host` runs with redirected output, so entrypoints clear through `Clear-MoleScreen`. [Core.Tests.ps1](../tests/Core.Tests.ps1) guards the WMI ban and [cmd/mo/main_test.go](../cmd/mo/main_test.go) covers the host boundary.

## CMD launchers and PowerShell binding

Do not turn paths or arguments into interpolated PowerShell source. The generated launcher uses `DisableDelayedExpansion` and native `-File` argument forwarding. Its `(goto)` transfer also supports removing the running batch file; changing that sequence can lose scoped environment variables, report a missing batch file or overwrite the child's exit status.

An ASCII batch cannot embed a pwsh alias under a non-ASCII user folder. Resolve a PATH-provided host with CMD's explicit `%%~$PATH:P` lookup before the existing transfer, so CMD expands the path at runtime and ignores a same-name executable in the working directory. A portable host outside PATH can use an existing environment-variable directory prefix when its remaining suffix is ASCII; escape literal percent signs and keep the shortcut's concrete path. Reject an unrepresentable host before creating, copying or refreshing installation files. The host-path cases in [InstallLifecycle.Tests.ps1](../tests/InstallLifecycle.Tests.ps1) execute both generated files and cover the shadow executable, portable paths and refusal before writes.

Root and command-local flags have different PowerShell binding paths: a long root help flag may arrive in remaining arguments, while a short help flag may bind to the root switch even for a child command. Exercise both routing and the real generated launcher. [InstallLifecycle.Tests.ps1](../tests/InstallLifecycle.Tests.ps1) covers special characters, command-local flags and exit status after self-removal.

When checking decoded JSON argument arrays in PowerShell 5.1, assign the decoded value before asserting its elements. Wrapping the conversion pipeline in an array can count one emitted array object rather than its individual arguments, falsely suggesting argument loss.

PowerShell pipelines unwrap a single result to a scalar. Keep a collection-shaped result with `@(...)` before inspecting its count or indexing it, and test zero, one and multiple matches. The real uninstall search found the one-match case that multi-match fixtures missed; [Uninstall.Tests.ps1](../tests/Uninstall.Tests.ps1) keeps that regression. `scripts/e2e_windows.py` found it on its first runs as the single-match search crash in `mo uninstall`, which Pester on pwsh 7 had hidden.

## Test isolation and false success

The remote e2e runner names `powershell.exe` explicitly: PowerShell can resolve bare `powershell` to an unrelated extensionless file before the installed executable. Its ASCII encoded wrapper keeps literal paths and arguments intact through either cmd or PowerShell, then uses the real `-File` invocation. Windows OpenSSH returned zero for an `exit 37` ConPTY command on both tested hosts, so terminal completion requires this run's `MOLE_EXIT` marker; a missing marker, nonzero command status or failed transport is not success. Keep output encoding local to the child session and aligned with the runner's UTF-8 decoder; a Chinese CP936 host otherwise corrupts JSON and transcripts. Preserve the actual error when a candidate version probe fails. `tests/e2e_harness_test.py` covers these boundaries without changing the host shell or locale.

A global `git` function left by one Pester file can intercept later tests that need the real executable. A passing isolated file does not prove suite isolation. Pester callbacks can also inherit the caller's local variables: a fixture named `$Health` resolved to `Main`'s health hashtable instead of its expected status string. Use a uniquely named, explicitly scoped fixture and inspect the runtime value before changing production logic. Keep mocks file-scoped, restore modified process environment in `finally` or teardown, and run the full suite after changes to shared mocks. [GitProxy.Tests.ps1](../tests/GitProxy.Tests.ps1) uses a local stub with Pester-managed mocks.

For process-tree timeout fixtures, have the parent record the spawned child PID immediately. Waiting for a cold child PowerShell to write its own PID can fail on CI even when cancellation works. Keep a positive child-existence assertion, verify termination, and bound fixture cleanup by both PID and start time; do not change production timeouts to accommodate the harness.

Menu-output tests launch one owned native process with redirected streams and bounded cleanup. Windows PowerShell 5.1 `Receive-Job` also consults Workflow adapters: a missing/empty persistence path can fail a menu test even when its own job started correctly. This reproduced on the unchanged baseline while the isolated menu case passed; avoid involving unrelated job adapters in a native-process test.

Use the runner's result and exit status, not a count of matching output lines. [TestRunner.Tests.ps1](../tests/TestRunner.Tests.ps1) executes child runners with real passing, failing, empty and skipped suites plus native Go failures. Keep positive controls alongside refusal cases; an always-failing runner is not a safety improvement.

A Windows PowerShell 5.1 wrapper with terminating error preference can turn a native child's diagnostic stderr into `NativeCommandError` and interrupt an otherwise running test suite. Redirect both native streams through the process API, then check its exit code and the structured Pester result. Run Pester from a guest-local source copy: repository-root discovery on a UNC path can fail before any test executes.

For Windows VM tests launched as SYSTEM, create a private fixture profile before starting jobs, and set process-local `USERPROFILE`, `APPDATA` and `LOCALAPPDATA`. Set `SystemTemp`, `TEMP` and `TMP` together to an unprotected fixture directory outside Windows and other protected roots. Setting only `TEMP` and `TMP` can leave Pester or .NET using the system temp directory. Do not change the host's permanent environment or weaken production protection for test fixtures. If Pester is installed outside standard module locations, prepend that directory to process-local `PSModulePath` so child PowerShell processes can find it too.

A long `prlctl exec` encoded command can report a guest-session error while a short command still succeeds. Confirm guest availability with a short read-only command, then stage the fixture script in the shared folder and invoke it with a short encoded wrapper. Keep the runner and its baseline files outside the source directory, or install-inventory tests will correctly reject them.

When copying a source archive from macOS, exclude AppleDouble `._*` files and extended attributes at export. Those metadata files can be discovered as tests or install entries on Windows. Inspect the extracted inventory before interpreting a new parse or discovery failure as a product bug. Keep machine-specific runners and temporary paths outside tracked documentation.

On physical Windows, keep the isolated temporary root short: fixture GUIDs plus realistic application paths can exceed Windows PowerShell 5.1 path limits before the test reaches production code. File symbolic-link fixtures separately require the creation privilege; do not count a fixture setup refusal as a passed protection test. Record it separately from the privileged VM/CI run. Keep Go deletion fixtures out of the protected Public tree as well: an intended positive fixture there is correctly refused before its target assertion. Never weaken production policy to make that fixture pass.

Pester's `TestDrive` sits under `%LOCALAPPDATA%\Temp`, so a filter such as `-match '\\AppData(\\|$)'` on a full path skips every fixture file and a "nothing changed" snapshot compares two empty lists. Filter relative to the fixture root. Keep such snapshots to files, by size and write time: the PowerShell host creates `AppData` under a fresh `USERPROFILE`, and a folder's write time moves after the fixture is built, neither of which the code under test wrote (2026-11-10, the `mo remove --dry-run` and purge preview tests).

A child process that inherits a console as stdin waits at `[Console]::ReadKey` or `Read-Host` instead of failing. CI has no console, so the same test passes or fails cleanly there and hangs when the suite runs from a desktop session. Give every child an empty stdin (`'' | & powershell.exe ...`), and treat a child still running after a few minutes as this, not as a slow test.

A script without `[CmdletBinding()]` ignores a switch it does not declare. An older `install.ps1` called with `-Uninstall -DryRun` uninstalls for real, and one called with `-DryRun` alone installs. Before passing a new preview switch to a script that may be older than the caller, read its parameters (`(Get-Command -Name $path -CommandType ExternalScript).Parameters`) and refuse when it is missing; when a red run needs the old script, exclude the cases that would run it for real and check afterwards that they did not run.

`[Environment]::GetFolderPath("StartMenu")` returns an empty string when the profile has no Start Menu folder, which a fixture `USERPROFILE` never has, and `Join-Path ''` throws. A default parameter value built from it fails before the function body can decide there is nothing to do.

A test of code that can write machine state (the user PATH, a shortcut) reads the real value first and puts it back in `finally` when it changed, then fails; a broken gate must not cost the test machine a PATH entry.

## Asynchronous Analyze actions

Two scans can target the same path and still represent different requests. Establish request identity before dispatch, then validate both identity and path when accepting results. Separately test that busy deletion rejects action keys and still permits quit. [lifecycle_test.go](../cmd/analyze/lifecycle_test.go) covers these boundaries; path equality alone or a busy rendering state does not enforce them.

## Native evidence and release evidence

Cross-compilation proves the Go source builds for Windows; it does not exercise PowerShell, junction behavior, shell recycling or CMD quoting. Use actual Windows fixtures for those surfaces and mock destructive third-party owner commands. Preserve dry-run and positive eligible-target controls alongside protected-target tests.

A passing CI run and pushed source do not establish delivery in signed packages. Keep source, native validation and release evidence separate in the development record, and verify the actual release channel before telling users an update contains a fix.

For resolved filesystem roots passed to native executables or System.IO, use `Resolve-Path.ProviderPath`. Its `Path` property can carry a PowerShell provider prefix for UNC shares: PowerShell accepts that spelling, but signtool rejects the file and archive entry slicing uses the wrong root length. The two cases in `Release.Tests.ps1` execute the signing and archive root assignments with distinct provider and native paths; both failed before the fix and passed under PowerShell 5.1 and 7.

On the x64 ThinkPad the complete suite runs from the maintainer's Mac through `mole-windows/scripts/thinkpad/tp.sh` (lease `thinkpad`), used when the VM's host is leased: send the working tree as a tar with `tp.sh put`, unpack it under the user profile, and start a detached runner with `tp.sh ups`, which runs in the signed-in desktop session and writes its logs to files that `tp.sh ps` reads back. Scoop's `pwsh` shim does not start from the SSH service session (`Could not create process`), so PowerShell 7 runs only through `ups`; Windows PowerShell 5.1 runs either way. A non-administrator run fails the two launcher symbolic-link cases. Because `mo update` follows this branch's head for source installs, PowerShell that has never run on Windows is not pushed: both hosts pass on the ThinkPad or the VM first, and CI confirms afterwards.

## Installer inventory and shared directories

A documentation-only change can still change uninstall behavior: the October 13 development notes were initially missing from the install inventory, and both PowerShell CI jobs failed. Every shipped nested file belongs in `Get-MoleInstallNestedFiles`; its inventory test is a required check even for docs. A familiar directory name such as `bin` or `scripts` does not establish ownership of all its contents. Merge installation files and remove exact known files, preserving unknown entries and nonempty Git metadata. Test a shared directory, a pre-created empty directory and a linked ancestor independently.

Release-source equivalence needs the release tag locally. A shallow branch clone may omit it even when the native source is unchanged; missing evidence must not silently select an older binary. Fetch tags through the existing install/update path and test unrelated source changes separately from native source changes.

## Parent selections and accounting

Whitelist canonicalization can add a second row for a junction's final path. Keep the pattern, literal root, directory prefix and wildcard flag associated for every added row; expanding only some parallel arrays makes later wildcards use another pattern or index past the end. [CleanupBoundary.Tests.ps1](../tests/CleanupBoundary.Tests.ps1) mixes junction, wildcard and literal rules in different orders and checks the final wildcard through the real removal sink alongside an eligible neighbor. Testing one junction alone misses this interaction.

Protecting a child path is insufficient when another entry point moves its whole parent. Analyze must inspect protected descendants at review and at its final recycle boundary, while uninstall additionally verifies surviving installed-app owners from a complete inventory rather than its filtered menu. Keep unknown ownership or incomplete traversal read-only. Keep registered path identity independent of removal eligibility: clearing a protected InstallLocation makes the display merger collapse distinct same-name registrations. Apply static path restrictions separately to recursive size measurement and the full content/ownership policy to leftovers; invalidate cached rows when changing either persisted identity or size. Store selection caches are also not removal authority: re-read the exact current package and reject protected metadata, sparse manifests and unknown manifest evidence. A failed read or missing required Package/Properties node does not prove that a package is independent of its desktop owner.

Owner pruning may retain most of its store. A preview lists the root but cannot call its full size reclaimable; a successful command can still release zero measurable bytes. Preserve that distinction through summary rendering. Empty PowerShell pipelines can produce no `Measure-Object` result under strict mode, so accumulating file lengths must handle an empty set explicitly. Native nonzero exit codes also do not throw automatically in Windows PowerShell 5.1: check `LASTEXITCODE` before counting success.

A service-mediated cleanup cannot inspect each protected descendant itself. Testing one invented child such as `root\x` does not prove a wildcard misses the subtree. Delivery Optimization checks a wildcard whose literal prefix can overlap the root, including an empty or drive-root prefix, against every ancestor and every entry below the root, without entering links; a match, a link, an unreadable entry or an unfinished walk keeps the root. Retaining on overlap alone turned any leading-wildcard row such as `*\node_modules` into a silent opt-out. [AppCacheSafety.Tests.ps1](../tests/AppCacheSafety.Tests.ps1) runs these patterns against a fixture tree in preview and real mode, with non-matching leading wildcards still clearing.

## Terminal cells and read-only Store sizes

Windows ConsoleHost's `LengthInBufferCells` can count a Chinese character as one cell, just like .NET format-field widths. Neither is an oracle for CJK alignment. Truncate and pad app/project names through `Format-SizeListEntry`; test the rendered menu with an independent ASCII/CJK cell count, not only the formatter. Keep size columns fixed while shrinking the name budget for narrow terminals.

A standard user can enumerate files inside an installed Store package while lacking `FILE_READ_ATTRIBUTES` on its WindowsApps ancestor. The deletion snapshot therefore returns unknown even when display sizing is possible. Use the bounded, no-follow, display-only `Get-AppxInstallSizeKB` for that inventory; never reuse its result as deletion authority or relax the cleanup snapshot. An incomplete or failed measurement remains unknown. Change the app-cache schema when correcting persisted size computation.
