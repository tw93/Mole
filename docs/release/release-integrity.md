# Release Integrity

Roomy treats release integrity as part of the product safety model. A release is not ready just because the binaries compile; users need a clear chain from tag to assets to installer behavior.

## Required Release Manifest

Every public tag should have a manifest in the release notes or linked from them with these fields:

```text
Tag:
Commit:
Release date:
Launch scope: CLI
Generated by workflow run:
Source archive SHA-256:
analyze-darwin-amd64 SHA-256:
analyze-darwin-arm64 SHA-256:
status-darwin-amd64 SHA-256:
status-darwin-arm64 SHA-256:
binaries-darwin-amd64.tar.gz SHA-256:
binaries-darwin-arm64.tar.gz SHA-256:
SHA256SUMS published: yes/no
Artifact attestation published: yes/no
Personal Homebrew tap updated: yes/no
Homebrew core PR/status:
GitHub release publication:
Release notes:
Landing page smoke check:
Clean-machine drill record:
Clean-machine drill evidence:
Formula publishing secrets validated:
Known limitations:
Rollback/remove notes:
```

## Pre-Draft Source Checklist

- `scripts/check-public-release.sh --tag <TAG> --full --skip-clean-machine` passes before release assets are created.
- The worktree is clean; no uncommitted or untracked source files remain before tagging.
- `scripts/release-preflight.sh` passes.
- `scripts/check-release-version.sh --tag <TAG>` confirms the tag matches `roomy`'s `VERSION`.
- If the tag already exists locally, it points at the release commit.
- `scripts/check-release-notes.sh --tag <TAG>` passes for `docs/release/notes/<TAG>.md`.
- `go test ./...` passes.
- The normal shell/API/native validation suites pass for the changed surface.
- `git diff --check` is clean.
- Generated artifacts such as `.build`, `.cache`, `.dmg`, and `node_modules` are not tracked.
- Release notes are curated and describe user-visible changes, safety changes, and compatibility impact.
- The release workflow validates the exact curated notes file used for the GitHub release body.

## Post-Tag Checklist

- Homebrew publishing runs only from the canonical `tw93/roomy` repository.
- Release assets include exactly the expected helper binaries, Homebrew tarballs, and generated integrity files; unexpected build artifacts fail the workflow before release creation, and the draft release uploads an explicit asset list rather than a broad `bin/*` glob.
- GitHub artifact attestations cover the same explicit helper binary, Homebrew tarball, checksum, manifest, and release-body asset list that the draft release uploads.
- The install script verifies downloaded release assets against `SHA256SUMS` and rejects missing, malformed, or non-matching SHA-256 entries.
- The GitHub release stays in draft state until release assets, checksums, and attestations exist.
- Formula publishing secrets, including `PAT_TOKEN` for the personal tap and `HOMEBREW_GITHUB_API_TOKEN` for Homebrew core, are present before the draft release is staged publicly.
- The GitHub release is staged as a prerelease before formula publication so Homebrew URLs never point at hidden draft assets.
- Formula publishing reads `SHA256SUMS` from the staged release into a job-owned temporary directory, rejects missing or empty checksum assets, and cleans the temporary download directory on exit.
- Formula publishing clones the personal Homebrew tap into a job-owned temporary checkout and cleans it on exit.
- The personal Homebrew tap formula references the new tag and matching checksums.
- Formula update tooling rejects malformed release tags and non-SHA-256 checksum inputs before modifying the tap.
- The Homebrew core update is opened successfully by the release workflow.
- The GitHub release remains a prerelease only for install-channel validation.
- A clean-machine drill validates Homebrew install, script install, update, and remove behavior against the staged release and uploaded release tap formula.
- The clean-machine drill record's `Commit SHA` matches the release commit being promoted.
- The clean-machine drill record includes SHA-256 digests for `transcript.txt` and `results.tsv`, and the verifier checks those digests against the generated, uploaded, or downloaded evidence files.
- Before stable/latest promotion, the release workflow revalidates the uploaded `RELEASE_BODY.md`, confirms it starts with the curated tag-specific notes, and confirms the appended manifest names the release commit.
- `scripts/check-public-release.sh --tag <TAG> --final --record <generated-record> --evidence <generated-evidence-dir-or-archive>` passes after the drill.
- The final stable/latest promotion runs only after the generated clean-machine drill record and local evidence pass.
- The release workflow verifies both `clean-machine-drill-<TAG>.md` and `clean-machine-drill-<TAG>-evidence.tar.gz` are visible release assets before stable/latest promotion.
- Before stable/latest promotion, the release workflow rechecks the full uploaded asset allowlist, verifies the uploaded `RELEASE_MANIFEST.md` tag and commit against the workflow ref, verifies the manifest's source archive checksum, compares manifest helper/tarball checksums with `SHA256SUMS`, and runs `sha256sum --check SHA256SUMS` against the downloaded helper binaries and Homebrew tarballs.
- The release workflow downloads the uploaded clean-machine record and evidence archive and validates the downloaded archive contents before stable/latest promotion. Public evidence URLs are also downloaded and inspected by the record verifier when no local `--evidence` override is supplied.
- If a formula update or install-channel drill fails after prerelease staging, leave the release as a prerelease for diagnosis so Homebrew URLs remain publicly downloadable. Do not promote it to stable/latest.
- The release contains or links to the validated clean-machine drill record for the tag.
- The release contains or links to the clean-machine drill evidence archive for the tag.

## Release Notes Rules

Release notes must be useful without reading the diff:

- Start with the compatibility and launch scope.
- Call out destructive-operation safety changes.
- Call out install/update/remove changes.
- Name any known limitation or skipped validation.
- Link to checksum and attestation verification guidance when available.
